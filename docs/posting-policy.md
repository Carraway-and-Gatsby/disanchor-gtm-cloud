# 게시 정책 및 계정 검토

> **2026-10-26 소유자 승인 배치:** [35건의 고정 문구·시각](gtm-automatic-publishing-2026-10-27-35.en-ko.md)을 별도로 승인받아 provider 예약으로 등록했다. 이 배치의 한도는 7일 X 21건(매일 3건)·Threads 14건(매일 2건)이며 반복 생성하지 않는다. 아래 초기 Cloud 워커의 10건/1일 1건 정책과 현재 6건 설정은 변경하지 않았다. 새 모델 문구의 무승인 게시 권한은 부여하지 않으며, 계정·문구·시각 변경 시 이 배치는 새 검토가 필요하다.

2026-10-24 기준. 계정 정지 위험을 낮추기 위한 보수적 운영 정책이며, 정지 방지를 보장하지 않습니다. 플랫폼 정책과 계정 상태는 운영자가 게시 활성화 전에 다시 확인해야 합니다.

## 허용 범위

- 소유자가 확인한 X 및 Threads 계정에 자체 작성한 텍스트만 게시합니다.
- 168시간 동안 총 10건, 채널별 최대 5건, 대상 시간대의 날짜별 채널당 1건입니다.
- 공식 Upload-Post API를 사용하고, X 웹사이트를 조작해 게시하지 않습니다.
- 모든 게시문은 검토 가능한 후보 라이브러리 또는 정확한 내용별 승인에 근거합니다. 승인되지 않은 모델 출력은 게시하지 않습니다.
- 초기 7일 실험 전체는 대화 중심으로 운영합니다. 제품 광고를 반복해서 붙여 넣지 않고, 그 자체로 유용한 컴퓨팅 관찰이나 실제 작업 흐름에 관한 질문으로 시작합니다. 자발적으로 공유하고 싶은 내용을 지향하되 바이럴 성과를 보장하지 않습니다.
- 실제 기술적 관심과 반복 작업의 문제를 다루며, 프로필에서 나이·성별을 추측하지 않습니다. 확인되지 않은 개인 경험이나 사용 후기를 만들지 않고 운영자와 제품의 관계를 숨기지 않습니다.
- **모든 게시문에서 Disanchor가 개발 중이라는 사실을 자연스럽게 전달합니다.** 별도 고지문을 말미에 붙이지 않고, `We're still building Disanchor, ...`처럼 글의 관찰·질문과 연결하거나 문장 안에서 아직 출시되지 않았음을 설명합니다. 같은 꼬리표의 표현만 바꾸어 반복하지 않습니다. 현재 개발 중이라는 사실만 1인칭으로 쓸 수 있으며, 없었던 개발 경험·인터뷰·고객 반응은 만들지 않습니다. 단순히 연구·탐색·검증 중이라고만 쓰거나 과거에 개발했다고 쓰는 것은 충분하지 않습니다.
- Windows 영속성, GPU 확장, 지연시간, 모바일 지원, 가격, 공개 이용 가능성을 확인된 기능처럼 쓰지 않습니다. 이미 출시됐거나 바로 사용할 수 있다는 인상을 주지 않습니다.

## 금지 및 중단

DM·이메일 발송, 무단 답글·멘션, 좋아요, 팔로우/언팔로우, 대량 재게시, 가짜 참여·트래픽, 유료 광고, 자동 결제·플랜 변경 기능은 없습니다. 감지를 피하기 위한 지연 조작, 계정 교체, 프록시 회전, 제한 우회도 하지 않습니다.

초기 7일 동안 X와 Threads 본문 모두 URL·도메인·링크를 사용하지 않습니다. 호스트가 뒤에 링크를 추가하는 것도 금지합니다. 프로필 방문·가입·대기명단·구매·데모 신청·접근권한 요청을 유도하지 않으며, 모든 후보의 `cta`는 `none`입니다. 기존 프로필 링크가 있더라도 게시문에서 방문을 요청하지 않습니다. 두 채널의 문구를 복제하지 않습니다. 이후 단계에서 링크나 전환 유도를 도입하려면 별도의 정책 변경과 소유자 검토가 필요하며, 7일 경과만으로 자동 활성화하지 않습니다.

작업 흐름에 관한 자연스러운 질문은 허용합니다. 좋아요·팔로우·공유·재게시·태그를 요청하거나, 댓글을 달아야 접근권한을 준다는 방식의 참여 유도는 금지합니다. 광고를 숨기거나 독립적인 고객인 척하는 방식으로 계정 위험을 줄이려 하지 않습니다.

정규화 중복 해시와 유사도 검사로 중복 문구를 차단합니다. 개발 상황을 설명하는 부분을 문장 중간으로 옮기거나 표현을 바꾸어도 같은 본문을 재사용할 수 없도록, 인식된 개발 설명과 구두점을 제외하고 내용을 비교합니다. 텍스트 길이에는 개발 설명도 포함합니다. 개인정보·비밀값 패턴, 허위 약속, 참여 유도 문구, 링크, 현재 개발 중이라는 맥락의 누락을 검사합니다. 고정 문장을 요구하는 검사가 아니며, 의미적 사실검증을 완전히 대체하지도 않습니다. 새로운 제품 주장과 문구는 소유자 검토가 필요합니다.

후보 라이브러리는 `organic-v3`, 정책 버전은 `2026-10-24.3`입니다. 정책 변경으로 기존 게시 승인은 무효화됩니다. 이미 저장된 초안을 자동으로 고쳐 승인하지 않으며, 새 문구는 정확한 내용으로 다시 검토합니다.

401/403/429 오류는 게시를 멈추고 승인을 취소합니다. 플랫폼 경고를 받으면 `incident --reason platform_warning`으로 중단합니다. 계정 문제가 해결되기 전에 재시도·다른 계정 이동을 하지 않습니다. 시간 초과는 UNKNOWN으로 유지하며 상태를 대조하기 전 새 요청을 만들지 않습니다.

## 활성화 전 소유자 검토

정확한 계정 식별자와 연결 권한, 공개 프로필의 운영 주체, X 프로필 링크, 남은 공유 업로드 수, 경고·제한 유무, 후보 문구, 현재 공식 정책을 확인합니다. `authorize`는 검토 사실을 기록하며 API 연결 자체를 검증해 주지 않습니다. 정지나 권한 취소 요청은 즉시 수용하고 예약 취소 결과까지 확인합니다.

## 공식 근거와 확인 한계

- [X 자동화 규칙](https://help.x.com/en/rules-and-policies/x-automation): 웹사이트 스크립트 자동화, 스팸, 중복 게시, 무단 상호작용, 계정 소유자의 명시적 동의를 다룹니다. 본문을 열어 확인했습니다.
- [X 진정성 정책](https://help.x.com/en/rules-and-policies/authenticity): 인위적 참여와 계정 조작을 금지합니다. 본문을 열어 확인했습니다.
- [Upload-Post 텍스트 API](https://docs.upload-post.com/api/upload-text/): 무료 X 텍스트 게시 및 링크 제한을 확인했습니다.
- [Meta 스팸 정책](https://transparency.meta.com/policies/community-standards/spam/): 이번 도구 접근에서 HTTP 429가 발생해 현재 본문 전체를 확인하지 못했습니다. 운영자는 Threads 활성화 전에 현행 약관·스팸 정책·연결 앱 권한을 직접 검토해야 합니다. 이를 검증 완료로 표시하지 않습니다.

게시량이 적다는 사실만으로 정책 준수나 계정 안전이 보장되지는 않습니다. 본 시스템은 유용한 자체 게시, 투명한 제품 설명, 보수적 중단 조건을 중심으로 설계되어 있습니다.
