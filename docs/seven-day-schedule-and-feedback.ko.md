# 7일 게시 계획과 댓글 조회 범위

확인일: 2026-10-25. 저장소 코드와 Upload-Post 공식 문서를 확인했습니다. 이번 확인은 오프라인 검증과 공개 문서 조회이며 실제 Cloud 인스턴스·댓글 권한·실시간 댓글 응답을 검증한 것은 아닙니다.

후속 실제 확인: [X·Threads 댓글 권한 점검과 필요한 설정](comment-permissions.ko.md). 로컬 연결 5개에 GET 13회를 실행했으며 X 2개 멘션 조회 성공·개인 Threads 부분 조회를 확인했습니다. 현재 선택된 공식 X·브랜드 Threads는 최근 글 목록이 비어 댓글 권한은 미확인입니다. 실제 Cloud 호스트는 여전히 미검증입니다.

**현재 실제 게시: 0건. API 게시 OFF, 유료 모델 OFF, 전체 예산 USD 20 유지.** Cloud 인스턴스 생성·캠페인 시작·예약 제출을 하지 않습니다. [영문·한국어 초안 14개](account-drafts.en-ko.md)는 검토 자료이며 게시 대기열이 아닙니다.

## 7일 동안 켜 두면 무엇이 게시되나

현재 잠금 상태로 Cloud를 7일 운영해도 **자동 게시되는 글은 없습니다.** Cloud 가동 시간과 실험 시작 시각은 별개입니다. 설치 wrapper는 `--no-publish`와 `GTM_POSTING_LOCK=1`을 적용하고, 실험 시작·승인도 차단합니다. 초기 staging에는 API 자격 증명을 넣지 않습니다.

아래는 향후 사용자가 별도로 실제 게시를 지시하고 모든 검토·권한·예산 검사를 통과한 경우의 **설정상 최대 10개 슬롯**입니다. 게시 약속이나 예약 내역이 아닙니다. 경고·권한 부족·문구 미승인·할당량 미확인·비용 미확인 시 해당 글을 보내지 않습니다.

현재 선택된 대상은 X `disanchor_x` → `@disanchor_com`, Threads `default_threads` → `@disanchor_com`입니다. 같은 핸들이어도 서로 다른 플랫폼이며, 계정마다 실제 native ID를 대조해야 합니다. 다른 5개 전략은 이 일정에 포함하지 않습니다.

| 실험 날짜 — 뉴욕 현지 날짜 기준 | X · 공식 @disanchor_com | Threads · 브랜드 @disanchor_com | 일별 최대 |
| --- | --- | --- | --- |
| D1 | 12:00 · `x_01` | 18:00 · `threads_01` | 2 |
| D2 | 12:00 · `x_02` | — | 1 |
| D3 | — | 18:00 · `threads_02` | 1 |
| D4 | 12:00 · `x_03` | 18:00 · `threads_03` | 2 |
| D5 | 12:00 · `x_04` | — | 1 |
| D6 | — | 18:00 · `threads_04` | 1 |
| D7 | 12:00 · `x_05` | 18:00 · `threads_05` | 2 |
| 합계 | 5 | 5 | 10 |

- 기준 시간대는 `America/New_York`, 보고 시간대는 `Asia/Seoul`입니다. 뉴욕 서머타임이면 한국에서는 다음 날 X 01:00·Threads 07:00, 표준시이면 다음 날 02:00·08:00입니다. 전환 주간에는 각 슬롯 날짜의 시차를 사용합니다.
- D1은 시작 시각이 속한 뉴욕 날짜입니다. D1의 정규 시간이 이미 지났으면 코드는 시작 후 X 10분·Threads 20분으로 계산합니다. 같은 날짜·168시간 범위를 벗어나면 일정을 거부합니다. 향후 실제 시작 전에는 첫 정규 시간보다 일찍 시작할 수 있도록 날짜별 UTC/KST 미리보기를 검토해야 합니다.
- 새 게시와 유료 모델 작업은 실험 시작부터 168시간까지만 허용됩니다. 늦거나 막힌 슬롯을 뒤에 몰아서 게시하거나 일정을 자동 연장하지 않습니다. 플랫폼당 뉴욕 날짜별 최대 1건, 플랫폼별 5건, 전체 10건입니다.
- 문구는 아직 슬롯에 배정하지 않았습니다. 14개 중 현재 선택된 두 계정의 글은 `OX-01/02`, `DT-01/02` 총 4개입니다. 나머지 6개 슬롯은 해당 계정에 맞는 새 문구·검토가 필요합니다. 다른 계정의 글을 복사해 채우지 않습니다. 기존 seed 라이브러리도 이 14개와 별개입니다.
- 10개는 최대치이며 채워야 할 목표가 아닙니다. 계정 상태에 따라 더 적게 게시하거나 중단합니다. 이 빈도가 플랫폼에서 계정 제한을 막아 주는 공식 허용치라는 뜻은 아닙니다.

시간표의 근거: [설정](../config.toml), [`DAY_PLATFORMS`·`slots`](../gtm/config.py), [24시간 이내 슬롯 처리](../gtm/engine.py). 날짜는 아직 확정하지 않았습니다. 선택형 Clone 시간 제안 기능도 현재 OFF입니다.

## Hermes가 돌리는 주기

아래는 [설치 스크립트](../scripts/hermes-install.sh)의 cron 정의입니다. 실제 Cloud에 설치하거나 실행하지 않았습니다. 간격은 작업 실행 주기이며 위 표의 게시 시각이나 실제 API 성공을 보장하지 않습니다.

| 작업 | 정의된 주기 · 최대 호출 횟수 | 역할 |
| --- | --- | --- |
| daily | 24시간 · 7회 | 학습·기획과 다음 24시간 슬롯 준비; 게시 잠금이 항상 우선 |
| collect | 8시간 · 21회 | 확인된 우리 게시물의 지표·댓글 표본 수집 |
| reconcile | 4시간 · 42회 | 외부 작업 결과 대조; 불명확한 결과 재전송 금지 |
| watchdog | 1시간 · 168회 | 실험 종료·안전 상태 점검 |
| report | 24시간 · 7회 | 현황 보고서 |
| telegram | 5분 · 2,017회 | 활성화한 경우에만 소유자 개인 현황; 현재 비활성 |

최초 작업 시각·예약 접수·재시작 복구는 배포 호스트에서 검증해야 합니다. staging의 게시 잠금은 cron을 설치했다고 해제되지 않습니다. 댓글 수집은 실시간 스트림이 아니며, 실험 미시작 또는 확인된 게시물 영수증이 없는 현재 상태에서는 수집 대상도 없습니다.

## 에이전트가 댓글을 읽을 수 있나

**조건부로 가능합니다.** 수집기가 공식 API로 표본을 읽어 메모리에서 분류하고, 모델과 skill에는 개인정보를 제거한 집계만 전달합니다. LLM에 댓글 원문을 모두 넣어 자유롭게 해석하도록 구현한 것은 아닙니다.

| 채널 | 제공자 공식 계약 | 현재 워커의 범위 |
| --- | --- | --- |
| X | 댓글 목록은 `source: mentions` 방식 | 멘션 표본만 수집. 모든 답글·전체 대화라고 해석하지 않음 |
| Threads | read-replies 권한이 있어야 다른 사람의 답글 조회 가능. 권한이 없으면 Upload-Post에서 작성한 답글만 보일 수 있음 | `partial: true`는 감성 미확인으로 처리. 후속 실조회에서 개인 계정은 partial, 현재 선택된 브랜드 계정은 미확인 |
| Instagram | 댓글 목록 API 제공 | 이 워커의 자동 수집·전송 대상 아님 |
| LinkedIn | 회사 Page 게시물 댓글 API 제공 | 이 워커의 자동 수집·전송 대상 아님. 개인 프로필 분석 미지원이며 Page 게시 주체도 재확인 필요 |

공식 근거: [Upload-Post Comments](https://docs.upload-post.com/api/comments), [Analytics API](https://docs.upload-post.com/api/get-analytics/). API 제공 범위와 이 저장소의 구현 범위는 다릅니다. 권한·제공자 계약은 바뀔 수 있으므로 향후 연결 시 다시 확인합니다.

- 조회 대상은 로컬 게시 영수증에서 `PUBLISHED` 또는 `CONFIRMED`로 확인되고 native post ID와 계정 지문이 있는 글뿐입니다. 임의의 남의 글이나 계정 전체의 과거 글을 수집하지 않습니다. 수동 게시물도 별도 검증 없이 자동 편입되지 않습니다.
- 수집마다 실제 연결 ID·만료 상태를 확인한 뒤 `GET /api/uploadposts/comments`를 사용합니다. 기본 한도는 수집당 우리 글 10개, 글당 댓글 레코드 40개·2페이지이며 계정 확인 GET이 추가됩니다.
- 원문·이름·핸들·작성자 ID·댓글 ID는 저장하거나 LLM·Telegram·보고서·skill로 보내지 않습니다. 본인 댓글·작성 주체 미확인·중복 ID·같은 문구는 제외하고, 연락처·URL·핸들을 지운 뒤 로컬 분류합니다.
- 영어·한국어 키워드로 긍정·부정·혼합·미확인을 집계합니다. 반어·모호함·부정 표현 등은 보수적으로 미확인에 둡니다. 분류 가능한 레코드 5개 이상, 분류율 50% 이상이어야 감성 방향을 표시합니다. 좋아요 수는 감성이 아닙니다.
- 권한 부족·서버 오류는 감성 `null`로 남기며 같은 실행에서 재시도하지 않습니다. 명확한 API 한도 오류는 진행 중 캠페인을 일시 중지하고 게시 승인을 해제합니다. 우회 조회는 하지 않습니다.

## 반응을 skill로 저장해 다음 글에 반영하는 방식

**우리 글의 지표·댓글 표본 → 계정별 검증 집계 → 버전이 있는 skill 생성·갱신 → 다음 리서치 → 기획 → 작성·실행 검토 → 사람의 정확한 문구 검토** 순서입니다.

재사용 가능한 관측을 만들려면 같은 계정·플랫폼·가설·도입 방식·노출 지표를 가진 글이 최소 3개이고 각 글의 노출이 100 이상이어야 합니다. 48시간보다 오래된 관측은 학습에서 제외합니다. 표본이 적으면 톤을 임의로 긍정적으로 바꾸거나 성공 전략으로 확정하지 않습니다. 7일·10개 슬롯만으로 이 조건을 못 채울 수 있습니다.

검증된 skill은 유용성·구체성·공감 정도를 계정 프롬프트의 허용 범위에서 조절하는 기획 근거입니다. 논란이나 부정 반응을 더 자극해 반응을 키우는 방식은 허용하지 않습니다. skill은 게시 승인·예산·계정·정책·게시량을 바꾸지 못합니다. native Hermes writer가 미설정이면 문서화된 native 형식 산출물을 사용하며, 실제 Cloud에서 native 도구 경로는 별도 확인이 필요합니다. [구현 상세](marketing-feedback.md) · [auto-skill](hermes-auto-skills.md) · [계정별 조절 기준](account-strategies.md).

자동 댓글 답변·좋아요·DM·AutoDM·타 계정과의 인위적 반응 교환은 하지 않습니다. 현재 OFF 상태에서는 게시도 댓글 학습도 시작하지 않습니다.

## $20 예산과 계정 보호

전체 $20 안에 Cloud·모델 최대 $5·외부 도구 최대 $2가 모두 포함됩니다. $14에서 경고하고 $18에서 신규 선택 유료 작업·게시를 차단합니다. 비용을 모르면 0으로 가정하지 않습니다. 현재 유료 모델은 OFF입니다.

이 문서는 새 요금 견적이 아닙니다. 실제 배포 전 Cloud 가동·정지 보관 비용과 제공자 비용 상한을 확인하고 최소 24시간마다 청구를 대조해야 합니다. 앱의 168시간 종료·cron 횟수 제한은 Cloud를 정지하거나 결제를 제한하지 않으므로, 나중에 운영을 끝내면 인스턴스를 별도로 정지해야 합니다.

개발 중 고지는 문장에 자연스럽게 넣고, 광고성 유도·중복 문구·예약 실패의 무조건 재시도·계정 제한 우회는 금지합니다. 플랫폼 경고는 중단 사유입니다. 계정 정지 위험을 낮추는 원칙이며 정지가 절대 없다는 보장은 할 수 없습니다. [배포 체크리스트](deployment-checklist.ko.md) · [게시 정책](posting-policy.md).
